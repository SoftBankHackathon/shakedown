# AWS ECS 실제 실행 실험 — 2026-10-09

승인 예산: 3 USD. 리전: 서울(ap-northeast-2). AI 생성 Flask 이미지를 Linux AMD64로 빌드하고 ECR digest를 고정했다. ECS에서 실행 중인 이미지 digest가 일치하는지 확인했다.

## 측정 범위

제품의 소·중·대 프리셋에서 CPU와 메모리 크기만 가져온 별도 실험이다. 각 실험은 태스크 1개·단일 AZ이며 ALB, 자동 확장, RDS는 생성하지 않았다. 제품의 선택한 설계안 → 실제 배포 연결을 구현하거나 검증한 것이 아니다.

PC에서 태스크의 공인 IP로 접근했으며 보안 그룹은 실험 PC의 IPv4 /32만 허용했다. 각 조건에 20초 동안 일정한 속도로 요청을 보냈다. 동시 미완료 요청은 최대 50개이며 대기 지연은 별도로 기록했다. 이 결과는 단순 JSON endpoint에 대한 실행 검증이며 서비스 최대 처리량이나 자원 증설 효과를 입증하지 않는다.

## 1차 결과

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.5 vCPU / 1 GiB | 5 | 100 | 0 | 40.7 ms | 86.25 ms | 129.73 ms | 22.39 s |
| 1 vCPU / 2 GiB | 50 | 1000 | 1 | 54.48 ms | 166.79 ms | 270.12 ms | 25.67 s |
| 2 vCPU / 4 GiB | 150 | 3000 | 0 | 46.38 ms | 105.64 ms | 150.49 ms | 25.85 s |

기동 시간은 RunTask 요청부터 HTTP 응답 확인까지다. 응답시간에는 PC↔AWS 네트워크 지연이 포함되고, 요청을 예약한 뒤 실행 대기한 시간은 포함하지 않는다. 최대 스케줄링 지연은 각 27.30/18.80/21.97ms였다.

중규모 1,000건 중 1건 실패는 숨기지 않고 기록한다. 첫 측정기는 오류 종류를 저장하지 않았으므로 원인은 미확정이다. 앱 로그에서는 정상 시작 및 테스트 종료에 따른 SIGTERM만 확인됐다. 후속 측정기에 실패 분류 기록을 추가했다.

## 중규모 재검증

같은 이미지 digest, 1 vCPU/2 GiB, 50 RPS/20초 조건으로 별도 태스크에서 1회 재검증했다. 1,000건 중 오류 0건, p50 40.74ms / p95 82.49ms / p99 113.35ms, 기동 22.24초, 최대 스케줄링 지연 26.84ms였다. 최초 1건 실패는 재현되지 않았으며 원인을 확정하지 않는다. 전체 AWS 요청은 5,100건, 실패는 합계 1건이다.

## 비용과 정리

첫 실행은 Docker 인증용 임시 설정에서 buildx를 찾지 못해 ECS 실행 전 종료됐다. 생성된 스택은 삭제됐다. 로컬에서 AMD64 이미지를 먼저 빌드하도록 수정한 재시도에서 위 결과를 얻었다.

1차 성공 실험 전체 경과시간은 340.29초이며 태스크 중지 및 스택 삭제가 완료됐다. ECR 이미지는 스택 삭제 시 제거되며 VPC·서브넷·IGW·보안 그룹·로그·실행 역할도 삭제 대상이다. 태스크 정의는 비활성화 후 삭제 요청했다. 기존 팀 스택은 수정하지 않았다.

서울 Linux/x86 Fargate의 확인 단가는 vCPU-hour당 $0.04656, GiB-hour당 $0.00511이다. 2 vCPU/4 GiB 한 태스크를 30분 유지해도 계산상 컴퓨팅 비용은 $0.05678이다. 이는 부대 비용·세금·최소 과금시간을 포함한 확정 청구액이 아니다. 실제 청구액은 집계 지연 때문에 미확정이다.

요금 출처: https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonECS/current/ap-northeast-2/index.json

재현 스크립트: infra/aws/experiments/fargate-smoke.py. 원본 증빙에는 계정·네트워크 정보가 있어 로컬의 Git 제외 디렉터리에 보관했다.

## 최종 정리 확인

재검증까지 완료한 뒤 세 실험 스택 모두 CloudFormation DELETE_COMPLETE를 확인했다.
해당 이름 접두사의 ECR 저장소, CloudWatch 로그 그룹, ECS 클러스터 목록도 모두 빈 목록이었다.
두 측정 실행의 cleanup_errors는 모두 빈 목록이며, 종료되지 않은 테스트 태스크는 없다.

성공 측정과 재검증의 전체 경과시간 합계는 499.55초다. 이 전체 시간에 가장 큰
2 vCPU/4 GiB 태스크가 계속 실행됐다고 과대 가정해도 컴퓨팅 비용 계산은 약 $0.0158이다.
여기에 IPv4/ECR/로그/전송 및 세금 등이 별도이며, 최종 청구액을 조회한 값은 아니다.
최초 실패 실행에서는 ECS 태스크가 생성되지 않았다. 3달러를 소진할 때까지
실행하지 않고 작은 실험으로 종료했으며, 과금 지속 리소스 정리를 확인했다.

제품의 자동 아키텍처 배포, ALB/RDS, 다중 태스크·다중 AZ·자동 확장 검증은 여전히 남아 있다.
