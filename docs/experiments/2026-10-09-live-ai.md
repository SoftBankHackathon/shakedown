# 실제 Claude API 및 생성 이미지 실행 검증 — 2026-10-09

모델: claude-sonnet-5-5. 로컬 엔진에 사용자가 연결한 키로 실행했다. 키와 원본 provider 응답/헤더는 이 문서에 포함하지 않는다.

## 실행 결과

| 요청 | 실제 결과 | 엔진 API 왕복 시간 |
| --- | --- | --- |
| Flask 규칙 미지원 → Dockerfile 생성 | ai-fallback, 구조 검증 통과 | 3.679초 |
| 5 RPS / 일시 중단 허용 / 일정한 트래픽 | small | 3.876초 |
| 50 RPS / 높은 가용성 / 급증 가능 | medium | 4.551초 |
| 150 RPS / 높은 가용성 / 급증 가능 | large | 4.434초 |

이미지 생성 1회, 아키텍처 판단 3회로 실제 API 호출을 검증했다. 숫자는 각 1회 관측값으로 모델 지연시간 분포나 품질 보장이 아니다. 토큰 사용량/청구 금액은 현재 엔진 응답에 없어 측정하지 못했다.

대규모 요구 계획에서 small 선택은 HTTP 400으로 거절됐고 large 선택은 HTTP 200으로 저장됐다.

## 생성 이미지 빌드 및 실행

테스트용 Flask 앱: requirements.txt에 Flask==3.1.0, gunicorn==23.0.0, app.py에 최상위 Flask app 및 JSON 응답 루트 경로를 구성했다. 기존 Dockerfile은 없었다.

AI 결과를 검토하고 엔진 빌드 API를 호출해 실제 Docker 이미지 빌드 성공을 확인했다. 결과는 python:3.12-slim, requirements 설치, app.py 복사, 비root 사용자, 5000 포트 및 gunicorn app:app 실행 명령을 포함했다.

생성 이미지를 0.5 CPU / 1 GiB 제한으로 실행했다. 포트는 127.0.0.1에만 바인딩하고 추가 권한/호스트 마운트는 주지 않았다. HTTP 200 및 예상 JSON 응답을 확인했다.

짧은 로컬 연속 요청 검증(동시성 10, 200건):
- 오류 0건
- 총 0.103초, 관측 처리율 1,943.80 req/s
- p50 4.19 ms / p95 4.87 ms / p99 8.48 ms

이 수치는 매우 짧은 단순 endpoint 기능 확인이다. CPU quota 기간, 워밍업, 지속 부하, DB 작업, 외부 네트워크를 평가하지 않으므로 운영 용량이나 AWS 성능으로 사용할 수 없다. 요청 대기열 진입 전 시간은 개별 응답시간에 포함되지 않는다. 테스트 컨테이너는 종료·삭제했다.

## 남은 실험

- 선택한 아키텍처를 실제 인프라에 적용하는 코드 연결은 아직 미구현이다.
- AWS 리소스는 생성하지 않았다. 기존 계정의 STS 및 Fargate quota 조회만 수행했다.
- AWS 예산 확정 후 별도 테스트 스택으로 측정해야 한다. 기존 사용자 스택은 변경하지 않는다.
- 실제 AWS 다중 AZ / 자동 확장 / RDS / 지속 부하 측정 및 테스트 리소스 정리가 남았다.
